## 1. Почему в Git ветвление дешёвое, а в SVN — дорогое?
В Git ветка — это просто лёгкий указатель, который ссылается на конкретный коммит. При создании ветки Git не копирует файлы проекта, а просто создаёт новую метку на текущем состоянии истории. Это происходит мгновенно и не занимает места.
В SVN ветвление исторически представляет собой физическое копирование всей директории с файлами на центральном сервере. Для больших проектов это требует значительного времени и дискового пространства, поэтому считается дорогой операцией.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет, в SVN сделать коммит без подключения к интернету невозможно. 
SVN — это централизованная система контроля версий. Вся история изменений хранится исключительно на одном центральном сервере. Чтобы зафиксировать изменения, клиент должен отправить их на этот сервер. В отличие от Git, где полная копия репозитория хранится локально у каждого разработчика, SVN требует постоянного соединения с сервером для любых операций записи.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
Несмотря на доминирование Git, SVN всё ещё используется в специфических сценариях:
1. **Legacy-проекты:** Старые корпоративные, банковские или государственные системы, которые разрабатываются уже 10-15 лет. Их миграция на Git слишком дорога и рискованна.
2. **Работа с большими бинарными файлами:** В сферах геймдева, дизайна или видео-продакшена, где в репозитории лежат гигабайты артов, 3D-моделей и ассетов. SVN поддерживает механизм файловых блокировок, который предотвращает конфликты при одновременном редактировании бинарных файлов несколькими людьми.
3. **Жёсткий централизованный контроль:** В организациях с строгими регламентами безопасности, где по политике компании весь код должен немедленно отправляться на центральный сервер, а локальное хранение полной истории не приветствуется.
